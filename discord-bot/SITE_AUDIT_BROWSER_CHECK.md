## 이미지 저장 수정 범위

관리자 이미지 업로드는 이제 이미지 저장소 업로드와 동시에 몬스터 메타데이터의 `imageUrl`을 영구 데이터 저장소에 기록한다. 몬스터 전체 저장과 엑셀 임포트는 기존 이미지 URL을 이름 또는 ID 기준으로 보존한다. 개발 환경 JSON 파일은 폴백·부트스트랩으로 유지하고, 운영 환경은 MySQL `monster_data_store`를 기준으로 사용한다.

## 추가 브라우저 확인

관리자 세션에서 `/admin` 대시보드와 **데이터 관리** 탭을 열어 정상 렌더링을 확인했다. 현재 화면에는 총 몬스터 793개, 조합법 있는 몬스터 692개, 현재 방문자 4명이 표시되며 엑셀 다운로드·파일 업로드 버튼이 정상 노출된다.

관리자 **몬스터 관리** 탭과 첫 헨치의 **수정** 화면도 정상적으로 열렸다. 이름·속성·레벨·서식지·Main/Sub·득코 여부·X항체 입력 영역이 표시되며, 수정 화면 하단에 이미지 업로드 영역이 이어지는 구조를 확인했다. 또한 최근 요구사항에 따라 관리자 대시보드 상단의 방문자 수 표시를 제거하고, 하단 통계를 2개 카드(총 몬스터, 조합법 있는 몬스터)로 정돈했으며, v3.3.0 업데이트 이력을 업데이트 탭과 서버에 추가하여 모든 사용자가 최신 변경 내역을 확인할 수 있도록 반영했다.

## 주요 공개 화면 점검

`/hench`가 영구 저장 데이터 793개를 조회했고, 속성별 개수·검색창·최소/최대 레벨·득코 필터·60개 점진 렌더링과 카드 이미지가 정상 표시되었다. 첫 화면에서 카드와 `상세정보` 버튼이 모두 렌더링되며, 콘솔 치명 오류는 확인되지 않았다.

`/calculator`가 정방향·역방향 탭, 메인·서브 몬스터 선택 입력, 레벨 입력, 초기화 버튼을 오류 없이 표시했다.

`/tree`가 몬스터 이름 검색 입력과 선택 전 안내 상태를 정상 표시했다. 검색·선택 UI가 데이터가 없어 깨지지 않고 빈 상태를 안내한다.

`/reverse`가 역산 믹스트리 제목·설명·몬스터 검색 입력과 선택 전 안내 상태를 정상 표시했다.

`/material`이 재료 계산기 제목과 헨치 이름 검색 입력을 정상 표시했다. 검색 전 빈 상태에서 화면이 깨지지 않는다.

`/feedback`가 유형 선택, 제목, 내용, 선택 이메일, 건의사항 전송 버튼과 서버 검토 안내를 정상 표시했다. 실제 제출은 테스트 데이터 생성을 피하기 위해 실행하지 않았다.

`/updates`가 v3.2.0부터 v2.0.0까지의 누적 이력과 서버·실시간 동기화 안내를 최신순으로 정상 표시했다.

`/members`가 전체 회원 4명, 승인 대기 0명, 승인 회원 4명, 정지 0명과 현재 접속 중 3명을 표시했다. 검색·상태 필터·대기·정지·탈퇴 버튼이 회원별로 표시되고, 관리자 계정은 보호되어 탈퇴 버튼이 표시되지 않는다.

실제 이미지 영구 저장 실측을 위해 관리자 세션에서 `/admin`을 다시 열었다. 대시보드에 총 몬스터 793개와 조합법 있는 몬스터 692개가 표시되며 기존 목록이 정상 로드된다.

실제 업로드 검증 대상은 첫 번째 헨치 `데빌코`로 선택했다. 수정 폼에 이름·속성·최소/최대 레벨·서식지·Main/Sub·Main2/Sub2·득코 여부·X항체 항목이 정상 표시되며, 아래쪽에 이미지 업로드 입력이 이어진다.

`데빌코` 수정 폼에서 이미지 입력이 실제로 존재하고 `accept="image/*"`로 확인되었다. 업로드 전 현재 데이터는 793개이며, 이 실측은 임시 1×1 PNG를 업로드한 뒤 서버 재시작·재조회까지 확인하고 원래 이미지 상태로 되돌리는 방식으로 진행할 예정이다.

브라우저 파일 입력은 DOM에서 확인되지만 자동 파일 업로드 도구가 두 차례 입력 요소를 찾지 못했다. 검증을 중단하지 않고, 동일한 관리자 세션에서 최적화된 이미지 데이터 URL을 이미지 API에 직접 보내는 실제 API 흐름으로 전환한다.

실제 관리자 세션에서 `데빌코`(id `a2f7ab59-db3e-49b4-a19e-a40a679d7bc7`)에 임시 WebP를 업로드했다. `/api/monster-image`가 HTTP 200과 `persisted: true`를 반환했고 저장 URL은 `/manus-storage/monster-images/a2f7ab59-db3e-49b4-a19e-a40a679d7bc7_3ab63ebb.webp`였다.

개발 서버 재시작 후에도 브라우저 세션이 유지되어 홈 화면이 정상 렌더링되었다. `/login` 주소 요청은 승인된 세션에 의해 홈으로 정리되었고, 홈의 속성별 통계와 주요 기능 링크가 표시된다.

재시작 후 `/api/monsters` 재조회에서 793개와 동일 임시 imageUrl이 유지되어 영구 저장을 확인했다. 원래 `imageUrl: null`로 복원하는 일반 POST는 기존 이미지 보존 병합 규칙 때문에 임시 URL을 유지했으므로, 데이터 손실 없이 명시적 이미지 제거 복원 절차를 별도로 수행한다.

서버 재시작 뒤에도 데빌코 imageUrl이 동일하게 재조회되어 영구 보존을 확인했다. 테스트 후 명시적 `imageUrl: null` 병합 규칙을 적용해 전체 몬스터를 다시 저장했고, 최종 재조회에서 793개 데이터와 데빌코 `imageUrl: null` 복원을 확인했다.

`/favorites`가 제목, 검색 입력, 즐겨찾기 없음 안내를 정상 표시했다. 빈 데이터 상태에서도 레이아웃과 안내 문구가 깨지지 않는다.

승인된 세션에서 `/register`와 `/pending` 요청이 모두 홈으로 정상 정리되었다. 이는 인증 컨텍스트가 승인 회원의 공개 진입 화면 재접근을 막는 기존 정책에 따른 동작이며, 라우팅 오류 화면은 발생하지 않았다.

이번 브라우저 점검은 기존 관리자 세션에서 수행했으며, 워터마크에는 `ABYSS서버 믹스사이트 · 관리자` 식별 문구가 표시되었다. 워터마크는 화면 표시 계층에만 적용되고 원본 저장 이미지 파일은 변형하지 않는다. 운영체제 수준의 스크린샷 자체를 완전히 차단하는 기능은 웹 브라우저에서 보장할 수 없으므로, 본 기능은 식별 및 무단 복제 억제 목적이다.


관리자 `/admin` 점검 결과: 화면이 정상 렌더링되었고 관리자 대시보드·회원 관리·로그아웃·몬스터 관리 탭이 표시되었다. 공개 화면에서 확인된 반복 워터마크는 관리자 경로에서는 표시되지 않았으며, 관리자 통계 카드에도 접속자 수 항목이 없어 기존 요청사항이 유지되었다. 문서 제목은 계속 `ABYSS서버 믹스사이트`로 표시되었다.


헨치 목록 `/hench` 점검 결과: ABYSS서버 믹스사이트 제목·사이드바·반복 워터마크가 정상 표시되고, 검색·속성 필터·레벨 입력·상세정보 버튼이 렌더링되었다. 기본 이미지가 없는 몬스터는 속성 아이콘을 사용하는 기존 동작이 유지되었다. 업로드 이미지가 있는 몬스터의 데이터 응답은 새 `/api/monster-image?key=...` 보호 프록시를 사용하도록 서버·클라이언트 변환을 추가했으며, 기존 캐시의 `/manus-storage/...` URL도 클라이언트 캐시 갱신 시 보호 URL로 변환하도록 보완했다.
